# Project Working Agreement

## Plan maintenance is required

The Markdown files in `plan/` are living project records. Every agent working in
this repository must keep them accurate throughout a task, not only when work is
finished.

Before making a meaningful implementation change:

1. Read `plan/README.md`, `plan/roadmap.md`, and `plan/progress.md`.
2. Update the roadmap or progress log when the intended work differs from the
   recorded plan.

While and after working:

1. Record completed work, verification results, blockers, and changed next steps
   in `plan/progress.md`.
2. Add or revise milestones in `plan/roadmap.md` when scope, priorities, or
   sequencing changes.
3. Record important technical choices and their reasoning in `plan/decisions.md`.
4. Keep entries concise, dated, and factual. Do not erase useful history; append
   a correction or superseding entry instead.

If a task makes no code changes, update the plan files when it produces a
decision, finding, or a change in project status.

## Explain every request

For every user request, include a clear, beginner-friendly explanation of how
the relevant feature, change, command, or concept works. State the outcome
first, then explain the important flow, components, and reasons behind the
approach. Keep the explanation proportionate to the request and avoid assuming
prior technical knowledge.
